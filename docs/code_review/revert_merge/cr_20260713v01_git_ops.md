## Implementation Plan

1. [completed] Match log level to caller intent - `code/revert_merge/git_ops.py`
   - 1.1. [completed] Lines 67-71: `run_git` logs a non-zero exit at `logger.error` unconditionally, even when the caller passed `check=False` to deliberately inspect a possibly-failing command. Per the Logging skill's level table, ERROR is for "failures that don't stop execution"; a non-zero exit the caller has opted into is closer to WARNING (or DEBUG). Emitting ERROR in that path produces misleading log noise for expected failures.
        - Current: `if result.returncode != 0:\n            logger.error(...)`
        - Expected: escalate to `logger.error` only when `check` is True (the path that raises); log at `logger.warning`/`logger.debug` when `check=False`.
        - Resolution: Moved the non-zero-exit log emission inside the branch on `check`. The failure message is now built once (`message`), logged at `logger.error` only in the `check is True` path immediately before the `CalledProcessError` is raised, and logged at `logger.warning` in the `check=False` path where the caller has opted into inspecting an expected failure. Chose WARNING over DEBUG so a deliberately-inspected non-zero exit still surfaces in normal logs without being flagged as an error.
