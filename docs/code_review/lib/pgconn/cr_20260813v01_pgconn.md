## Implementation Plan

1. [completed] Align dotenv loading and the env-var error message with their documented contracts - `code/lib/pgconn/pgconn.py`
   - 1.1. [minor] Line 75: `load_dotenv()` is called with defaults, and python-dotenv defaults to `interpolate=True`, which expands POSIX-style `${VAR}` references inside `.env` values (verified against the installed package: a value `pre${FOO}post` loads as `prebarpost`; a bare `$` does survive). This contradicts the docstring's claim on lines 46-48 ("literal values — no shell expansion, so secrets containing `$` survive intact") — a password containing `${` is silently rewritten before reaching the connection kwargs. Passing `interpolate=False` makes the documented contract actually hold; note the companion test fake must accept the new call signature (see finding 1.1 in `docs/code_review/lib/pgconn/unit_tests/cr_20260813v01_test_pgconn.md`).
        - Current: `load_dotenv()`
        - Expected: `load_dotenv(interpolate=False)`
        - Resolution: Implemented as specified — `load_dotenv(interpolate=False)` with a comment explaining why interpolation is disabled; verified against the installed python-dotenv that `${FOO}` now survives literally. The companion test fake was widened in the same changeset (finding 1.1 in `docs/code_review/lib/pgconn/unit_tests/cr_20260813v01_test_pgconn.md`).
   - 1.2. [minor] Lines 76-80: the presence check `not os.environ.get(name)` deliberately treats a set-but-empty variable as unusable (sensible — an empty host or password cannot connect), but the raised message says only "Missing required env var(s)", which is misleading when `.env` contains e.g. `POSTGRES_PASSWORD=` set-but-empty; the exception-handling skill calls for accurate context in error messages.
        - Current: `f"Missing required env var(s) in environment/.env: {missing}"`
        - Expected: `f"Missing or empty required env var(s) in environment/.env: {missing}"`
        - Resolution: Implemented with an added accommodation — the message now reads "Missing or empty required env var(s)..." (wrapped across two f-string segments for line length), and the docstring's `Raises:` entry was updated to "missing or empty" so the documented contract matches the behavior.
