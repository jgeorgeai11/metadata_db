## Implementation Plan

1. [completed] Anchor the publicly exported schema pattern - `code/lib/pgconn/pgconn.py`
   - 1.1. [minor] Line 40: `SCHEMA_NAME_RE` is compiled unanchored. The one internal use is `fullmatch` (line 68), so `connection_kwargs` itself is safe, but the constant is re-exported as a public contract constant (`code/lib/pgconn/__init__.py` lines 7 and 9, and its docstring calls it a "contract constant" — see `docs/code_review/lib/pgconn/cr_20260813v01___init__.md` finding 1.1). Any consumer that reaches for the exported pattern with `.match()` or `.search()` silently accepts exactly the values the comment on lines 29-39 says are excluded: `SCHEMA_NAME_RE.match("catalog -c search_path=public")` succeeds, as does `.match("bad-name")`. Anchoring makes the compiled object encode the documented shape on its own, independent of which method a caller picks, and leaves the existing `fullmatch` call and all 23 tests passing unchanged.
        - Current: `SCHEMA_NAME_RE = re.compile(r"[a-z_][a-z0-9_]*")`
        - Expected: `SCHEMA_NAME_RE = re.compile(r"\A[a-z_][a-z0-9_]*\Z")`
        - Resolution: Implemented as specified (line 47) with an added accommodation — extended the block comment above the constant to state why it is anchored (the constant is re-exported as a contract constant, so an unanchored pattern would let a consumer using `.match()`/`.search()` accept the values the comment lists as excluded), since the anchors are otherwise unexplained next to the internal `fullmatch` call. Behavior-neutral for the module's own use: the suite is green (24 passed, 100% coverage of `pgconn.py`) and `fullmatch` is the only in-repo use of the pattern.

2. [completed] Document that the process environment, not `.env`, is the authoritative source - `code/lib/pgconn/pgconn.py`
   - 2.1. [minor] Lines 3-5 and 45-47: both docstrings describe credentials as coming from `.env` ("credentials come from `.env` (the four `POSTGRES_*` variables)"; "Loads the `.env` file ... and reads the `POSTGRES_*` components"). `load_dotenv` defaults to `override=False`, so a `POSTGRES_*` variable already exported in the process environment wins over the `.env` entry, and the values are then read straight from `os.environ` (lines 87-90) whether or not a `.env` file exists. This is the path CI actually takes: `.github/workflows/pre_merge.yml` lines 173-176 and `post_merge.yml` lines 166-169 supply the four variables as job `env:` values with no `.env` file in the checkout. The docstrings skill calls for documenting the "why" and keeping docstrings current with behavior; as written they mislead a maintainer debugging why an edited `.env` value did not take effect. Only the docstring text changes — no behavior change.
        - Current: `credentials come from `.env` (the four `POSTGRES_*` variables)` (module docstring) and `Loads the `.env` file (literal values — no shell expansion, so secrets containing `$` survive intact) and reads the `POSTGRES_*` components.` (function docstring)
        - Expected: state the precedence explicitly, e.g. module docstring "credentials come from the four `POSTGRES_*` environment variables — exported in the environment (how CI supplies them) or, for local development, loaded from `.env`; an already-exported variable wins, since `load_dotenv` does not override" and a matching clause in the function docstring's first paragraph
        - Resolution: Implemented as specified — the module docstring now reads "credentials come from the four `POSTGRES_*` environment variables — exported in the environment (how CI supplies them) or, for local development, loaded from `.env`; an already-exported variable wins, since `load_dotenv` does not override", and the function docstring's first paragraph now leads with the process environment being authoritative, notes that `.env` only fills in names not already exported (because `load_dotenv` does not override), and states that no `.env` file need exist. The summary line changed from "from `.env` plus a DB + schema" to "from the env plus a DB + schema" to match. Text only — no behavior change; the `.env`-is-literal (`interpolate=False`) rationale was kept in place.
